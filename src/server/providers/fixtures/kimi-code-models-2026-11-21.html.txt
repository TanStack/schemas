class="custom-block-title" data-v-39e71d9e>Before you switch</p><ul data-v-39e71d9e><li data-v-39e71d9e><strong data-v-39e71d9e>Start a new session</strong>: switching models or thinking effort Whether the request succeeds also depends on account permissions, thinking mode, and context limits. Check the error message:</p><ul data-v-39e71d9e><li data-v-39e71d9e><strong data-v-39e71d9e>Your account doesn&#39;t have access to the model or 1M context (403)</strong>: your current plan doesn&#39;t include the requested capability. <a href="#model-overview" data-v-39e71d9e>Check plan requirements in the model table</a>, then <a href="https://www.kimi.com/code/#pricing" target="_blank" rel="noreferrer" data-v-39e71d9e>go to Membership subscription →</a> as needed.</li><li data-v-39e71d9e><strong data-v-39e71d9e>Thinking is disabled (400)</strong>: K3.1 Pro models only support thinking mode. Compact long context, or switch to a model and plan that supports up to 1M.</li></ul></details><details class="details custom-block" data-v-39e71d9e><summary data-v-39e71d9e>How can I preserve model quality and reduce usage?</summary><p data-v-39e71d9e>Keep the same model and thinking effort within a session instead of switching back and forth. Switching models or thinking effort invalidates the existing context cache, requiring a new prefill and increasing token usage. Reasoning chains from different models can also affect each other.</p></details><details class="details custom-block" data-v-39e71d9e><summary data-v-39e71d9e>Why isn&#39;t Highspeed noticeably faster?</summary><p data-v-39e71d9e>Two common reasons:</p><ul data-v-39e71d9e><li data-v-39e71d9e><strong data-v-39e71d9e>Mistyped model ID</strong>: the Highspeed ID must be <code data-v-39e71d9e>k3.1-pro-highspeed</code> or <code data-v-39e71d9e>kimi-for-coding-highspeed</code>; a wrong value silently falls back to K2.8 Preview without thinking — no speedup.</li><li data-v-39e71d9e><strong data-v-39e71d9e>Tools and scripts dominate</strong>: Highspeed only speeds up <strong data-v-39e71d9e>model output</strong>. Tool calls (reading/writing files, running commands, etc.) and script execution are unaffected, so when they take up most of a turn the overall speedup feels small.</li></ul></details><details class="details custom-block" data-v-39e71d9e><summary data-v-39e71d9e>Switching between K3 (1M) and K3-256k</summary><p data-v-39e71d9e><strong data-v-39e71d9e>Switching from K3 (1M) to K3-256k</strong>: if the current session&#39;s context already exceeds 256k, some coding tools (such as Kimi Code CLI and Claude Code) will perform a compact on the tool side. Recommendations:</p><ol data-v-39e71d9e><li data-v-39e71d9e>Manually run compact once before switching to compress the context to within 256k. This preserves the key points of the task, keeps the session intact, and lets you benefit from more durable quota after switching.</li><li data-v-39e71d9e>If the conversation history includes video files, switching directly will fail because K3-256k does not support video input. Please compact first, then switch.</li></ol><p data-v-39e71d9e><strong data-v-39e71d9e>Switching from K3-256k to K3 (1M)</strong>: if <code data-v-39e71d9e>k3-256k</code> is close to the 256k limit and you don&#39;t want compact to lose information, you can switch directly to 1M.
